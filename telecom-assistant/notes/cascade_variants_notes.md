## 1. Policies

All four route to the judge whenever the symbolic verifier abstains. They differ
only in when a symbolic *commit* is allowed to stand.

| policy | symbolic is authoritative when |
|---|---|
| V0 | it commits at all, PASS or FAIL. This is the published Table 3 cascade. |
| V1 | it commits FAIL. A symbolic PASS routes to the judge. |
| V2 | a successfully parsed prior expression existed to compare against. |
| V2-literal | the step counter is > 1, on each testbed's own counter. |

V2 and V2-literal exist because the specification "step_index > 1 AND the prior
parsed" names two conditions that coincide on one testbed and diverge on the
other. See §6.

## 2. Gates

Both gates pass before any variant row is printed.

```
Gate 1: V0 must reproduce the published Table 3 exactly ... OK (all cells, both testbeds, both judges)
Gate 2: V1 on the human set must equal the judge alone ... OK
```

Gate 1 checks every cell, not just the four rates quoted in `CLAUDE.md`'s prose:
coverage, precision, recall, FPR, abstain rate, TP, FP, TN, FN, AbsE, AbsN,
total, and the three routing counts. A policy that matched on rates but not on
confusion cells would still be wrong.

## 4. Findings

### F1. V0 reproduces published Table 3 exactly

Gate 1, above. Every cell of all four V0 rows matches the published cascade, so
the variant rows below it are computed by machinery that is known to reproduce
the published one. This is the only reason the rest of the table is worth
reading.

### F2. V1 on the human set is bit-identical to the judge alone

Compare the two `V1 / human` rows against the two `judge-alone / human` rows.
Every cell agrees, for both judges. The routing counts say why: `sym = 0`. The
verifier decides nothing at all.

This is a structural property, not a measurement. On the human set the verifier
commits **zero FAIL verdicts**: TP=0 and FP=0, and all 90 of its commits are
passes. V1's rule is "symbolic FAIL is authoritative, symbolic PASS routes to
the judge", so on a testbed with no symbolic FAILs there is nothing for the
verifier to be authoritative about, and all 191 items reach the judge. Any
policy in which a symbolic PASS does not veto the judge is identical to the
judge alone here, by construction. Nothing was learned from running it; the
value of the row is that it confirms the harness does not perturb an
unperturbed policy.

### F3. V2's human-set gain for claude is exactly Q03.1 and Q10.1

Claude's recall goes 0.385 -> 0.538 under V2, TP 5 -> 7. The two recovered
errors are `Q03.1` and `Q10.1`, the two first-step definitional passes from
Table 5.

Under V0 these are symbolic committed passes on steps a human labeled wrong, so
they are false negatives. V2 withholds the verifier from them because neither
had a parsed prior to compare against, they route to claude, and claude commits
FAIL on both. They become true positives.

gpt-oss gains nothing: its recall is 0.231 under both V0 and V2, TP 3 -> 3. It
receives the same two steps under the same policy and **passes both**, so they
stay false negatives. The gain is a property of which judge is downstream, not
of the routing rule.

| item | error type | symbolic | gpt-oss | claude |
|---|---|---|---|---|
| Q03.1 | definition | PASS (first_step) | passed | failed |
| Q10.1 | definition | PASS (first_step) | passed | failed |

### F4. The 5 mid-derivation false passes survive every policy that lets a symbolic PASS stand

The verifier has 7 committed passes on error steps, and `CLAUDE.md` keeps them
split 5 mid-derivation + 2 first-step. The split is exactly what determines
which policy can recover which:

| item | error type | verifier category | recovered by V2? |
|---|---|---|---|
| Q03.1 | definition | first_step | yes |
| Q10.1 | definition | first_step | yes |
| Q09.3 | algebra | passed | no |
| Q09.4 | algebra | passed | no |
| Q09.11 | definition | passed | no |
| Q22.7 | missing_term | passed | no |
| Q22.9 | missing_term | passed | no |

The 5 `passed` rows had a parsed prior and were compared against it. V2's test
is satisfied, the verifier stays authoritative, and its wrong PASS stands. They
remain false negatives under V0, V2, and V2-literal alike. Only V1 reaches them,
because only V1 refuses to honour a symbolic PASS, and it routes all seven to
the judge. On the human set that is the same thing as not cascading at all
(F2), which is the trade: the only variant here that can see the 5 hardest
misses is the one that discards the verifier entirely.

### F5. V1 surrenders the injection FPR advantage

Injection, claude: FPR 0.130 -> 0.286, precision 0.968 -> 0.938, FP 3 -> 6. The
V1 row is identical to claude alone. gpt-oss no longer moves at all: it commits
no injection false positives under any variant, so its FPR is 0.000 throughout.

The routing counts locate the loss precisely: `sym` falls 42 -> 22. On injection
the verifier commits 42 items, 22 FAILs and 20 passes, and its 20 committed
passes are all correct negatives (TP=22, FP=0, TN=20). V1 keeps the 22 FAILs and
routes the 20 covered negatives to the judge, which is where the extra false
positives come from. The verifier's whole FPR advantage on this testbed lives in
those 20 items; a policy that hands them to the judge gives the advantage back.
V1 keeps V0's recall (0.894 / 0.957, unchanged for both judges) and pays for
nothing.

### F6. V2 is vacuous on injection

```
note: injection/gpt-oss-120b:  0/118 trials have no parsed prior; step_index values present: [1, 2]
note: injection/claude-sonnet-4-5: 0/118 trials have no parsed prior; step_index values present: [1, 2]
```

`step_index` on the injection suite is 0-based: `run_suite` iterates
`range(1, len(steps))`, so the first step is never mutated and `step_index` 1 is
the *second* step of a derivation. Every one of the 118 graded trials therefore
has a parsed prior expression, V2's condition is satisfied everywhere, and V2
collapses onto V0. All four `V2 / injection` cells equal their `V0 / injection`
counterparts.

V2-literal reads the same spec as `step_counter > 1` and so withholds the
verifier from the 79 second-step trials, `sym` 42 -> 11. That costs gpt-oss
recall nothing on the refreshed data (0.894 either way, TP 84, AbsE 0) and buys
nothing: its FPR is 0.000 either way. For claude it reproduces the standalone judge exactly, giving
back the FPR advantage as V1 does. The gap between V2 and V2-literal on this
testbed is entirely an artifact of which base the counter is read in, which is
why both are reported rather than one being picked silently.

### F7. Q09.2, and why V2 is penalized for being right about it

This is the single step on which V2 and V2-literal disagree, and it accounts for
the whole difference between their human-set rows (claude FP 15 -> 16, gpt-oss
FP 2 -> 3, and correspondingly TN 159 -> 158 and 176 -> 175).

The mechanism, end to end:

1. **Q09.1 does not parse.** Its expression is
   `Piecewise((1, Abs(t) < T0/2), (-1, Abs(t) < T0 and Abs(t) > T0/2))`. The
   `and` is a Python boolean operator sitting between two SymPy relationals, so
   evaluating it forces `bool()` on `Abs(t) < T0` and sympify raises
   `TypeError: cannot determine truth value of Relational: Abs(t) < T0`. The
   step is filed `parse_fail`.
2. **`prev_expr` is never assigned.** It initialises to `None`
   (`src/verifier.py:552`) and is only set from a successfully parsed
   expression. Q09.1 failing to parse leaves it `None`.
3. **Step 2 takes the first-step branch.** At `src/verifier.py:681` the verifier
   hits `elif prev_expr is None`, sets `is_valid = True` with
   `error_message = "First step"`, and returns. `equivalence_checked` is set
   only in the `else` branch below it, so it stays `False`.
4. **Nothing was compared.** Q09.2 is recorded as a committed symbolic pass, but
   the verifier never looked at a prior expression. It is an unverified step
   wearing a PASS.
5. **It scores as a true negative under V0 anyway**, because the step happens to
   be correct: `human_correct = True`, `error_type = none`. The label agrees
   with a verdict that was not earned.

V2 is the only policy that recognises Q09.2 as unverified. Its condition is
"a parsed prior existed", which is false here even though the step counter is 2,
so V2 alone routes it to the judge. V2-literal's `step_counter > 1` is true, so
it leaves the unearned PASS in place.

And V2 is punished for it. **Both judges are wrong about Q09.2**: gpt-oss
commits FAIL at confidence 0.92 and claude commits FAIL at 0.85, both objecting
to the integration limits, on a step the human labeled correct. Routing a
correct step to a judge that fails it converts a true negative into a false
positive. So the policy that correctly identifies the one step the verifier
never checked is the policy whose precision drops for doing so, on this item,
against these two judges. That is a coincidence of the downstream graders, not a
defect in V2's rule, and it should not be read as evidence against the rule.

This also means the 30-vs-29 no-prior count is not a rounding detail:

```
note: human set: 30/191 steps have no parsed prior; 29 of those are at
      step_number 1, 1 at step_number > 1 (predecessors all unparseable)
```

30 = 28 `first_step` at step 1, plus Q09.1 (`parse_fail` at step 1), plus Q09.2
(`first_step` at step 2). Of those 30, 29 carry a committed symbolic verdict, so
`sym` is 61 under V2 and 62 under V2-literal.

## 5. Caveat on the human-set gain

F3's gain is **2 of 13 errors**. Thirteen errors is not a sample from which a
recall difference can be estimated; a single relabeled step moves claude's V2
recall by 0.077. Every human-set number in this file should be read as
directional evidence about a mechanism, not as an effect size. The mechanism
itself is not in doubt, since it is fully determined by which steps had a parsed
prior and is verifiable item by item in §4. The magnitude is.

The injection rows carry 94 error trials and are correspondingly firmer, but
they are synthetic mutations of 9 hand-authored gold derivations, not a sample
of naturally occurring model errors.

## 6. What this does not license

- No variant here beats the published V0 cascade on both recall and FPR on
  either testbed. V1 and V2-literal trade the verifier's FPR advantage for
  recall the judge already had; V2 buys human-set recall for claude and pays for
  it in precision, and does nothing at all on injection.
- The V2 human-set rows depend on the Q09.2 judgement call in F7 and on 13
  errors. They are not an operating point.
- None of these were selected out of sample. Reporting them as tuned
  alternatives to Table 3 would be in-sample selection on a 13-error testbed.
